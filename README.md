# LeanTrain

LeanTrain 是一个探索中的 AI 训练框架：以主存/统一内存为中心，把 GPU、NPU 等加速器视为可调度的协处理器，而不是把训练系统完全围绕单一加速器显存来组织。

## 愿景

当前训练框架通常默认“数据与状态尽量驻留在加速器显存中”，主机内存更多承担数据加载、缓存和溢出角色。LeanTrain 反过来把内存层级作为一等公民：

- 以主存为训练状态、参数、优化器状态和中间表示的中心调度空间。
- 将 GPU/NPU/其他专用加速器抽象为执行算子、微批、通信或压缩任务的协处理器。
- 通过显式的数据移动、预取、换入换出和重计算策略，让训练可以跨越单卡显存限制。
- 面向异构硬件：在可用设备、带宽、容量和算子支持不断变化时，仍能组织稳定的训练执行。

## 核心目标

1. **Memory-first execution**：训练计划优先围绕内存容量、带宽、生命周期和数据局部性展开。
2. **Accelerator-as-coprocessor**：GPU/NPU 暴露为任务执行资源，调度器决定何时、何地、以何种粒度使用它们。
3. **Explicit data orchestration**：数据移动是计划的一部分，而不是隐藏副作用。
4. **Composable training runtime**：支持从单机实验逐步扩展到多设备、多节点和混合加速器。
5. **Research-friendly**：便于验证新的调度、检查点、重计算、分片、压缩和异构执行策略。

## 初步架构草案

```text
+---------------------------------------------------------------+
|                         User API / DSL                         |
|        model definition · optimizer · schedule hints           |
+------------------------------+--------------------------------+
                               |
+------------------------------v--------------------------------+
|                         Planner / IR                           |
| graph capture · tensor lifetimes · memory plan · task graph    |
+------------------------------+--------------------------------+
                               |
+------------------------------v--------------------------------+
|                         Runtime Scheduler                      |
| memory residency · prefetch/evict · recompute · device queues  |
+-----------+------------------+------------------+-------------+
            |                  |                  |
+-----------v----+   +---------v------+   +-------v------------+
| Host Memory    |   | GPU Worker(s)  |   | NPU / Other Worker |
| state center   |   | coprocessor    |   | coprocessor        |
+----------------+   +----------------+   +--------------------+
```

## 关键设计问题

- Tensor/parameter/optimizer state 的默认驻留位置是什么？
- 如何表达显式数据移动，同时不让用户 API 过于底层？
- 调度器如何在显存容量、PCIe/CXL/NUMA 带宽、算子耗时之间做权衡？
- 重计算、检查点、offload、分片和压缩如何统一进同一个计划模型？
- GPU 与 NPU 能力不同、算子覆盖不同、精度支持不同，应如何建模？
- 训练正确性、确定性和可复现性如何在异步调度下保证？

## 近期路线图

- [ ] 定义最小 IR：张量、算子、依赖、生命周期和内存位置。
- [ ] 实现单机原型调度器：主存中心状态管理 + 单 GPU 协处理执行。
- [ ] 跑通一个最小训练例子：线性模型或小型 Transformer block。
- [ ] 加入显式 prefetch/evict 与简单成本模型。
- [ ] 评估 optimizer state offload、activation checkpointing 和 recompute 策略。
- [ ] 设计异构 worker 接口，为 NPU/其他加速器预留后端。

## 非目标（当前阶段）

- 不追求立刻替代 PyTorch/JAX 等成熟训练框架。
- 不优先做完整分布式训练栈。
- 不先优化所有算子性能；先验证内存中心调度模型。
